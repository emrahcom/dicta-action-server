# Startup

Read and check the configuration and the site context at startup, then listen,
per `architecture.md` (Configuration, Site context) and `contract-context.md`.

- Environment variables as in `architecture.md` (Configuration). The server does
  not start, and says why, when a required one is missing or a value is not
  valid: `JWT_SECRET` shorter than 32 bytes, `PLANNER` other than `stub`,
  `MAX_ROUNDS` not a whole number from 1 to 100. A warning is logged when
  `ALLOW_UNAUTHENTICATED` is on.
- The site context is read from `CONTEXT_FILE` and checked as
  `contract-context.md` (Checks) says. The server does not start with a missing
  or invalid file, and says which field is wrong.
- Then the server listens on `PORT` and logs one line. Every request gets `404`
  for now.
- Tests for each refused value and each context check. A startup test that
  expects an exit stops the server and fails at once when it starts instead, so
  a missing check does not hang until the test timeout.
