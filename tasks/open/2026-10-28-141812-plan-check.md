# Plan check

Check every plan before it is sent, per `architecture.md` (Planner) and
`contract-plan.md` (Steps, References, Failures, Limits).

- The server keeps the site context it loads at startup and checks each plan
  answer against it. A plan that fails the check is not sent; the round gets a
  stop instead.
- A plan is valid when:
  - it has `steps`, an array of at most 50 steps, and `final`, when present, is
    a boolean; nothing else;
  - each step is a `call` with `args`, or a `forEach` with `as` and `do`, where
    `do` holds only `call` steps; nothing else;
  - each `call` names a capability of the context, and its `args` match the
    capability's schema (`type`, `properties`, `required`, `items`, `enum`); a
    reference stands for any value;
  - each reference points to an earlier top-level step or to the `as` of the
    `forEach` it is in, and `forEach` itself refers to an earlier step; `$$`
    starts a plain string;
  - a capability that `navigates` is called only in the last step, never inside
    a `forEach`.
- Unit tests for each rule, and one test over HTTP that a stub plan which fails
  the check gets a stop.
