# Claude planner

Add the `claude` planner, as `specs/architecture-planner.md` and
`specs/architecture-planner-claude.md` describe.

- Configuration (`specs/architecture.md`, Configuration): `PLANNER=claude`,
  `ANTHROPIC_API_KEY` required with it, `CLAUDE_MODEL` and `CLAUDE_EFFORT` with
  their defaults. The server does not start with a missing key or an effort that
  is not one of the five.
- `src/planners/claude.ts`: the instructions, with the reply format, the plan
  format, the limits and the rules for the LLM (`architecture-planner.md`); the
  prompt in its order with the two cache points; one Messages API call through
  `@anthropic-ai/sdk`, with the key given to the SDK, cancelled at the 45 s
  limit; the answer parsed as one JSON object; the failures of
  `architecture-planner-claude.md` (Failures) as planner failures; one log line
  per call with the model, the effort, the time and the token counts.
- Tests answer the SDK's HTTP calls with fixed responses, so no test calls the
  real API: the prompt's parts in order with the cache points on the right
  blocks; the site context written the same way in every round; a plan, a
  question and done parsed; an answer that is not JSON, `max_tokens`, a refusal,
  an API error and the 45 s limit each giving a stop; the startup checks.
- A short manual check against the real API with one Teamboard-like request, run
  once and reported, not part of `npm run test`.
