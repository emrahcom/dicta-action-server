# Test cleanups

Test fixes from the code quality review of 2026-11-20. The tests check the same
behaviour as before, with less repetition, in the file a reader would look in.

- `test/helpers.ts`, new: what several test files share, such as the context
  fixture, a round body builder, the test server with `start` and `post`, one
  `token` builder, and a counting planner.
- `test/server.test.ts`, new: the tests of `src/server.ts` move out of
  `test/round.test.ts`: tokens and audience, CORS and 404, `413`, the round log
  and the nested body. The four `401` tests become one table.
- `test/round.test.ts`:
  - the tables that post a changed body and expect `400` with a message become
    one table, and the bad bodies are written in the same way, with their
    messages;
  - the step text and progress cut tests become rows of the cut table;
  - repeated objects, such as a plan with an empty report and the plan limits,
    become constants;
  - the question and info tests that differ only in the reply become one table,
    and the info limit test that the limits table covers goes.
- `test/claude.test.ts`: helpers for the user blocks and the last part of the
  prompt; the instruction tests become one table named for what it checks.
- `test/index.test.ts`: the server under test starts with only `PATH`, `PORT`
  and the test's own settings, so settings in the shell, such as
  `PLANS_PER_CHECKPOINT` or `JWT_AUDIENCE`, cannot change the results.

Check: `npm run check`, `npm run lint` and `npm run test` pass, with no test
lost.
