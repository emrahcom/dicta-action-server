# Reply check

Check every reply of the planner before it is sent, not only plans
(`contract-protocol.md`, Response body; `architecture.md`, Planner).

- `type` is `plan`, `question`, `done` or `stop`.
- A question and a stop have a `text`, a string. A done may have one.
- A question's `options`, when present, is a list of strings.
- A `text` is at most 200 characters (Unicode code points). There are at most 5
  `options`, each at most 50 characters (`contract-protocol.md`, Limits).
- A reply that fails the check is never sent: the round gets a stop instead, and
  the reason is logged as a warning, as for a plan.
- The response body's `answer` becomes `reply`, and the code says reply for the
  server's reply: the type, the functions and the stub (`contract-protocol.md`,
  Response body). The user's `answer` to a question stays.
- Tests for each.
