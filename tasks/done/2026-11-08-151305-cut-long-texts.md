# Cut long texts

A text or an option over its limit no longer fails the reply check: the server
cuts it and sends the reply (`contract-protocol.md`, Response body and Limits;
`contract-plan.md`, Limits).

- The `text` of a question, done, stop or info: at most 2000 characters.
- The plan label: at most 200 characters, cut before the plan is checked, so the
  size check sees the cut plan.
- Each option: at most 50 characters.
- A cut text keeps its first characters and ends with `...`, the whole within
  the limit. Characters are Unicode code points, as today.
- Each cut is logged with `console.warn`, as a reply not sent is logged now,
  with the field and its length, never the text itself.
- Wrong types, a missing text, more than 5 options and every other check still
  fail the check and send a stop, as now.

The prompt already asks for 200 characters, 2000 for an info and 50 for an
option (`architecture-planner.md`, Rules for the LLM); it does not change.

Tests: the tests that expect a long text, label or option to fail expect the cut
instead, at the limit and one over it, with a character outside the BMP at the
cut.

Check: `npm run check`, `npm run lint` and `npm run test` pass.
